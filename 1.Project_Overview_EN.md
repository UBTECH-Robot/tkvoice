# Project Overview

## 📋 Project Summary

**TKVoice** is an **offline speech interaction system** project integrated with UBTech's TiangongLine (Unbounded/Boundless) robots, featuring speech recognition (ASR), large language models (LLM), and text-to-speech (TTS) capabilities. It enables end-to-end offline speech conversation abilities.

---

## 🏗️ System Architecture

### Hardware Deployment
```
├── x86 Server (192.168.41.1)  → ASR Service (Funasr)
├── Orin Board (192.168.41.2)  → LLM Service (Ollama) + TTS
└── RK3588s Device             → Audio Acquisition Device
```

### Data Flow Process
```
RK3588s Audio Stream
    ↓
[tk_audio_publisher] Acquire Complete Sentence Audio
    ↓ (audio_sentence_frames topic)
[tk_asr_text_publisher] Speech Recognition
    ↓ (asr_sentence topic)
[tk_audio_process] LLM Understanding + TTS Synthesis
    ↓
AudioPlayer Playback Output
```

## 🚀 Dependencies and Deployment

### System Dependencies
- **ROS 2** - Middleware Framework
- **Python 3** - Programming Language
- **Docker** - Container for x86 Server

### Third-Party Services
- **Funasr** - Speech Recognition Model Service
- **Ollama** - Large Language Model Inference Framework
- **Piper-TTS** - Offline Speech Synthesis Library

### Installation Steps
1. x86 Server: Install Docker + Funasr image
2. Orin Board: Install Ollama + Pull qwen2.5:1.5b model
3. Orin Board: Deploy audio_service ROS package

## 🎯 Key Features

### ✅ Advantages
- **Completely Offline** - No cloud dependency, fully local processing
- **Low Latency** - Real-time interaction without network constraints
- **High Reliability** - No network dependency, no cloud service account required
- **Cost Effective** - One-time deployment, no service fees
- **Modular Design** - Clear ROS publish-subscribe architecture
- **Multi-Hardware Support** - x86 + ARM (Orin/RK3588s) architecture

### ⚠️ Considerations
- **High Resource Requirements** - Funasr, Ollama, and other models consume significant resources
- **Network Dependency** - Three devices require local network communication
- **GPL-3.0 License** - TTS module brings GPL-3.0 compliance requirements
- **Complex Initialization** - Multiple services need manual configuration

## 🔄 Technology Flow Explanation

### Audio Processing Pipeline

```
User Speech Input (RK3588s Microphone)
         ↓
    [Audio Acquisition]
    Socket TCP :9080
         ↓
Orin Board: tk_audio_publisher
    Receives and buffers audio
         ↓
    [ROS Topic: audio_sentence_frames]
         ↓
Orin Board: tk_asr_text_publisher
    - Subscribes to audio
    - Creates WebSocket connection
    - Communicates with x86 Funasr
    - Receives recognition results
         ↓
    [ROS Topic: asr_sentence]
         ↓
Orin Board: tk_audio_process
    Core Processing Node:
    ├─ Subscribe to recognition results
    ├─ Call Ollama LLM via HTTP
    ├─ Get streaming response
    ├─ Call Piper TTS for synthesis
    └─ Play audio via AudioPlayer
         ↓
    [Complete Sentence Speech]
         ↓
AudioPlayer Output
    Playback and wait for next query
```
